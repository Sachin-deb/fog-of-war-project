# How to reproduce my entry

## Summary

- **Entry:** release `entry-1` (pre-tournament)
- **Approach in two sentences:** a residual CNN (994,885 parameters) reads a history-based
  encoding of everything my side has observed and predicts, for every legal move, the win
  probability that full-board Stockfish 19 gives that move, blended for the move actually played
  with that game's result (outcome weight 0.3); the agent plays the move with the highest
  prediction. It is trained on five rounds of games, from reference bots and noisy full-board
  Stockfish (round 0) through DAgger (round 1) to three league rounds played by the previous
  round's network against its predecessors, the baseline, Stockfish players and bots.
- **One command:** `bash scripts/get_stockfish.sh && bash reproduce.sh`

## 1. Environment

- Python 3.11 or later (I used 3.13.5), then `pip install -e ".[baseline]"`.
- Exact versions I used are in `requirements-lock.txt` (`pip freeze`); the ones that matter are
  torch 2.14.1, chess 1.11.2, numpy 2.5.4, safetensors 0.8.0.
- Stockfish 19: `bash scripts/get_stockfish.sh` downloads the pinned `sf_19` release into
  `stockfish/` and prints the `export STOCKFISH=...` line. `reproduce.sh` uses that path by default.
- On Sol: `bash scripts/sol/setup_env.sh` once.

## 2. Pipeline

Every stage is one case in `training/pipeline.sh`; `reproduce.sh` runs them in order. All data
is generated by the code; nothing is downloaded except Stockfish. Each label is a Stockfish 19
MultiPV search at depth 8 on the true board that scores every legal move (`training/teacher.py`).

| Stage | What it does | Output | Time (mine) |
|---|---|---|---|
| `gen0` | 60,000 games between reference bots and noisy full-board Stockfish | 1,262,078 positions, `data/r0` | 50 min |
| `train0` | network on round 0 | `checkpoints/r0` | 1.5 min |
| `gen1` | 40,000 games played by `r0` (DAgger) | 1,077,767 positions, `data/r1` | 46 min |
| `train1` | network on rounds 0-1 | `checkpoints/r1` | 2.5 min |
| `gen2` | 60,000 league games: `r1` against itself, `r0`, the baseline, noisy Stockfish and bots | 1,838,101 positions, `data/r2` | 84 min |
| `train2` | two networks on rounds 0-2: outcome weight 0 (`r2_l0`) and 0.3 (`r2_l0.3`) | `checkpoints/r2_l0`, `checkpoints/r2_l0.3` | 10 min |
| `gen3` | 60,000 league games played by `r2_l0.3`; also stores result-only positions | 4,023,325 positions (1.6M labelled), `data/r3` | 73 min |
| `train3` | two networks on rounds 0-3: with the result-only positions (`r3`) and without (`r3_nomc`) | `checkpoints/r3`, `checkpoints/r3_nomc` | 25 min |
| `gen4` | 60,000 league games played by `r3_nomc` against all earlier networks and the rest of the league | 2,102,086 positions, `data/r4` | 88 min |
| `final` | the entry: rounds 0-4, outcome weight 0.3 on rounds 2-4, result-only positions ignored | `submission/` | 12 min |

Data stages are CPU only (30 worker processes; the networks play on CPU). Train stages use one
GPU. The intermediate networks and the result-only positions of round 3 are needed because
later rounds play against them; they are not part of the entry.

**On Sol:** `bash scripts/sol/run_all.sh` submits the stages as a chain of jobs
(`scripts/sol/generate_data.sbatch` for data, `scripts/sol/train.sbatch` for training), each
starting after the previous one succeeded. One stage can be rerun with
`STAGE=<stage> sbatch --export=ALL,STAGE=<stage> scripts/sol/<script>`.

## 3. Training

`training/train.py`, 6 epochs, seed 0: AdamW, one-cycle learning rate 2e-3, batch 1024, bf16
autocast, the whole dataset held in GPU memory (the final stage fits on my 32 GB RTX 5090). Losses:

- q head: BCE to the teacher's per-move win probabilities; for the move actually played in
  rounds 2-4, the target is 0.7 × teacher + 0.3 × game result (`--outcome-lambda 0.3
  --outcome-from data/r2 data/r3 data/r4`);
- soft policy cross-entropy to the teacher's values (temperature 0.03);
- value BCE, belief cross-entropy on hidden squares, and a danger head (does this move leave my
  king capturable on the true board), weight 0.5.

## 4. Building `submission/`

`train.py --out submission` writes `submission/config.json`, `submission/weights/model.safetensors`
and `submission/train_log.json`. The code in `submission/` (`agent.py`, `features.py`,
`model.py`) is committed as is; `config.json` sets `"select": "q"` and `"mix_margin": 0.01`.

## 5. Expected results

- `python -m fow.validate submission --device cuda` prints VALID with 994,885 parameters and
  about 1.2×10⁸ FLOPs per move. My weights have SHA-256
  `1ce155870376c5f59e6ffa20b4eb078a95f2a7e7821b6abb29f487901309b506` (a rerun will differ; see 7).
- `submission/train_log.json`: validation q-head regret about 0.032, policy top-1 agreement
  with the teacher about 35%.
- Local rating about 1530 on the course scale (my run: 1534, 95% interval [1479, 1618]; it beat
  guess-sf-16x1000 91/100) from
  `python -m fow.arena submission agents/baseline bot:guess-sf-16x1000 bot:guess-sf-4x500 bot:greedy --games 100 --workers 4 --device cuda --official --seed 9`.
  The reference bots are weak relative to the entry, so this rating has a wide interval; the
  league networks are a better yardstick (in my run the entry scored 120/200 against `r2_l0.3`).
  Use at most about 8 workers on one GPU: with 16, some agent processes ran out of GPU memory.

## 6. Compute used in total

About 5 h 40 min on 30 CPU cores for data (about 170 core-hours) and about 50 minutes of GPU
time for the seven training runs. Total wall clock for `reproduce.sh` on my machine (32 CPU cores,
one RTX 5090): about 6 h 30 min. On Sol the data jobs request the same 32 cores. Development,
pilots and evaluation matches were run on the same machine; see `submission/MODEL.md`.

## 7. Known sources of variation

- **Data:** the games depend on the seed and on `--workers` (games are split per worker), and
  Stockfish's multi-PV search at fixed depth is deterministic with one thread, so with the same
  `WORKERS=30` the data should repeat; a different worker count gives a different but equivalent
  sample.
- **Later rounds depend on earlier networks:** from round 1 on, the previous networks play the
  games, so any difference in them changes the later games.
- **Training:** GPU training is not bit-reproducible; expect validation regret within about
  ±0.001 and strength within the 100-Elo replication tolerance. Two of my networks trained with
  the same recipe for 6 and 10 epochs scored 100-100 against each other.
