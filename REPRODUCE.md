# How to reproduce my entry

## Summary

- **Entry:** release `entry-1` (pre-tournament)
- **Approach in two sentences:** a residual CNN (984,773 parameters) reads a history-based
  encoding of everything my side has observed and predicts, for every legal move, the win
  probability that full-board Stockfish 19 gives that move; the agent plays the move with the
  highest prediction. It is trained on two rounds of data: games between reference bots and a
  noisy full-board Stockfish player, then games played by the round-0 network itself (DAgger).
- **One command:** `bash scripts/get_stockfish.sh && bash reproduce.sh`

## 1. Environment

- Python 3.11 or later (I used 3.13.5), then `pip install -e ".[baseline]"`.
- Exact versions I used are in `requirements-lock.txt` (`pip freeze`); the ones that matter are
  torch 2.14.1, chess 1.11.2, numpy 2.5.4, safetensors 0.8.0.
- Stockfish 19: `bash scripts/get_stockfish.sh` downloads the pinned `sf_19` release into
  `stockfish/` and prints the `export STOCKFISH=...` line. `reproduce.sh` uses that path by default.
- On Sol: `bash scripts/sol/setup_env.sh` once.

## 2. Data

All data is generated by the code; nothing is downloaded except Stockfish.

| Step | Command | Output | Time and hardware (mine) |
|---|---|---|---|
| Round 0: 60,000 games between reference bots and a noisy full-board Stockfish player; half of the positions labelled | `python training/gen_data.py --round 0 --games 60000 --workers 30 --depth 8 --out data/r0 --seed 0` | 1,262,078 positions, 182 MB in `data/r0/` | 50 min, 30 CPU cores |
| Round 1: 40,000 games played by the round-0 network (against itself, bots and noisy Stockfish) | `python training/gen_data.py --round 1 --games 40000 --workers 30 --depth 8 --out data/r1 --seed 1 --agent-dir checkpoints/r0` | 1,077,767 positions in `data/r1/` | 46 min, 30 CPU cores |

Each label is a Stockfish 19 MultiPV search at depth 8 on the true board that scores every
legal move; see `training/teacher.py` and `training/README.md`.

## 3. Training

| Stage | Command | Seed | Time and hardware (mine) |
|---|---|---|---|
| Round-0 network | `python training/train.py --data data/r0 --out checkpoints/r0 --epochs 6 --seed 0` | 0 | 83 s, one RTX 5090 |
| Final network | `python training/train.py --data data/r0 data/r1 --out submission --epochs 6 --seed 0` | 0 | 155 s, one RTX 5090 |

AdamW, one-cycle learning rate 2e-3, batch 1024, bf16 autocast, the whole dataset held in GPU
memory (about 3 GB). Losses: q-head BCE to the teacher's per-move win probabilities, soft
policy cross-entropy (temperature 0.03), value BCE, belief cross-entropy on hidden squares.

## 4. Building `submission/`

`train.py --out submission` writes `submission/config.json`, `submission/weights/model.safetensors`
and `submission/train_log.json`. The code in `submission/` (`agent.py`, `features.py`,
`model.py`) is committed as is; `config.json` sets `"select": "q"` and `"mix_margin": 0.01`.

## 5. Expected results

- `python -m fow.validate submission --device cuda` prints VALID with 984,773 parameters and
  about 1.2×10⁸ FLOPs per move.
- `submission/train_log.json`: validation q-head regret about 0.032 and policy top-1 agreement
  with the teacher about 34% (round 0 alone: 0.0335).
- Local rating about 1570 on the course scale (my run: 1567, 95% interval [1496, 1672]) from
  `python -m fow.arena submission checkpoints/r0 agents/baseline bot:greedy bot:guess-sf-4x500 bot:guess-sf-16x1000 --games 100 --workers 8 --device cuda --official --seed 2`.
  Use at most about 8 workers on one GPU: with 16, some agent processes ran out of GPU memory.

## 6. Compute used in total

About 1 h 36 min on 30 CPU cores for data (about 48 core-hours) and under 5 minutes of GPU time
for the two training runs. Development, pilots and evaluation matches were run on my own machine
(32 CPU cores, one RTX 5090); see `submission/MODEL.md`. Total wall clock for `reproduce.sh`:
about 1 h 45 min on that machine; on Sol the CPU job is the same size (32 cores).

## 7. Known sources of variation

- **Data:** the games depend on the seed and on `--workers` (games are split per worker), and
  Stockfish's multi-PV search at fixed depth is deterministic with one thread, so with the same
  `--workers` the data should repeat; a different worker count gives a different but equivalent
  sample.
- **Round 1 depends on round 0:** the round-0 network plays the round-1 games on CPU, so any
  difference in it changes the round-1 games.
- **Training:** GPU training is not bit-reproducible; expect validation regret within about
  ±0.001 and strength within the 100-Elo replication tolerance.
